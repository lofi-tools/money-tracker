# Desktop stage 6: local portfolio browser

Implemented slice: [Tauri host](../../apps/desktop/src-tauri/src/main.rs), [snapshot controller](../../apps/desktop/src-tauri/src/lib.rs), [Solid frontend](../../apps/desktop/src/App.tsx), [typed transport](../../apps/desktop/src/api.ts), and [run instructions](../../apps/desktop/README.md).

## Boundaries and behavior

The host resolves the existing shared local configuration, owns one `DatabaseWorker`, and caches one `PortfolioProjection`. Rust returns a versioned exact snapshot; asset/provider navigation, selected allocations and scoped details all derive from it. Monotonic snapshot IDs reject stale requests after settings/requery. Frontend requests contain selection/node identities; it performs search and expansion, not portfolio sums, APY calculations or financial sorting. Decimal units and rational numerators/denominators stay strings.

Overview opens by default and displays only current value and current net earnings per year. By asset is the initial navigation mode; By provider, ticker/name search, Dust and descending-value order consume Rust projections. Assets dust everywhere fold into Dust; an asset significant anywhere retains its full combined total, including dust holdings elsewhere. Asset selections retain providers as breakdown parents; provider selections start at accounts. Initially expand provider parents and top-level accounts, exposing their immediate children. Details preserve the visible allocation tree and expansion. Liability leaves show positive borrowed magnitudes separately from annual earnings/costs; net earnings subtract evidenced borrowing costs once.

Missing rate, price, attribution and balance evidence stays explicit. Row/provider warnings display coverage codes and the names of withheld/partial figures. Raw diagnostic messages are intentionally omitted because they can contain private mismatch quantities. Details show full exact quantities through the shared privacy formatter, original account references, current source dates and available subscription lock/maturity/renewal metadata. Hidden mode masks all rendered amounts/quantities; scaled mode uses the saved exact common factor and keeps rates visible. Names/references remain visible by design.

Settings persist reporting asset, theme, privacy scale, dust threshold and future refresh preferences through the worker. System theme follows the OS. Invalid settings are validated in Rust before applying their financial/display inputs. Selecting Hidden applies immediately while the preference is saved. No refresh executes in this stage, even when its future preference is enabled. Existing adapters do not yet populate generic exact price/rate/verification evidence: an imported DB may therefore show quantities and predominantly unknown annual earnings/value. Legacy float prices are not converted or fixture rates substituted.

There are seven app commands: startup, start new, copy database, allocation, details, save settings and quit. No SQL, arbitrary file path, network/credential, import or financial-edit IPC exists. The native picker selects the copy source in Rust; destination stays the configured DB path. The webview has no filesystem/shell/plugin permissions, remote navigation or remote asset dependencies; CSP limits script/connect sources. Copy validates/migrates the destination and preserves source bytes. Errors redact financial diagnostics; they do not silently replace invalid data.

Window close, OS Quit and explicit Quit await the worker and exit. No background owner/tray is created. No new migration or provider behavior is introduced. Low-level manual actions already exist in Rust, but their UI and persistent Undo remain stage 7. Acquisition/scheduling remains stage 8; all-platform packaging/signing remains stage 9.

## Validation

Desktop service tests exercise missing/new/copy/reopen/settings/close, source preservation, stale snapshot rejection, exact large quantities, partial totals, liability classification and selection-scoped details. A deterministic wire fixture is generated from actual Rust Session output for browser acceptance; it is ignored and never shipped. Browser acceptance checks navigation, detail focus/expansion, privacy, themes/settings, warnings, empty/missing states and accessibility. Offline private checks browse temporary copies of existing Nexo/Binance DBs without printing amounts or mutating their sources.

Local validation passed: 162 deterministic existing production-workspace tests (private/live acquisition excluded), three deterministic desktop service/query tests, and the opt-in offline desktop browse check on all three cached DB copies. Nexo and Binance statement copies contain current holdings; the Binance API cache is empty and remains an empty portfolio. All source bytes stayed unchanged. Nine formatting unit tests, six design-system browser regressions and three desktop browser acceptance tests passed, including axe accessibility. TypeScript, production builds, formatting, locked metadata and CLI help passed.

The macOS ARM64 native binary and local `.app` bundle built successfully. Native WebKit browsing against a temporary Nexo copy verified default Overview, asset/provider navigation, account expansion, scoped warning/details and explicit Quit with process exit. Direct window-close UI automation could not be completed because the computer-use surface reported the app had changed; the CloseRequested handler uses the same awaited shutdown path as Quit, and native close acceptance remains in stage 9. No provider request or original database navigation/migration was performed. The test app retains a temporary copy for local inspection.

The Tauri CLI needs `rustc` on PATH; this machine's global Cargo wrapper finds Rust internally but does not expose rustc to other executables. Use the repository's Rust development environment (or put the matching compiler on PATH). The initial deterministic provider suite failed under the filesystem/network sandbox because its localhost mock servers and macOS system-proxy lookup were restricted; it passed when run with those local test operations allowed. Native Linux/Windows builds and hosted workflow execution remain unverified. The existing Linux Rust job explicitly excludes the Tauri crate until the native build lane is configured; frontend CI includes the desktop production/typecheck outputs.

References for the host integration: [Tauri project setup](https://v2.tauri.app/start/create-project/), [native dialog API](https://v2.tauri.app/plugin/dialog/). The host pins Tauri 2.12.1 and tauri-build 2.7.2; the initial broad dependency selection mixed an older host with newer runtime APIs and failed compilation, so compatible stable versions are pinned and locked.
