## Decisions
- `libs/nexo-csv` owns CSV reading and deserialization. `apps/cli/src/adapters/nexo.rs` owns Nexo transaction semantics, conversion to `lib-core` types, and import orchestration. The CLI calls the adapter.
- Nexo's CSV records amounts to eight decimal places. The import stores each movement in integer units of 10^-8 and records the scale per asset.
- `nexo-csv` reads and hashes the exact file bytes with SHA-256. The Nexo adapter checks the hash before parsing or mapping. DuckDB stores the hash under the Nexo source only in the same transaction that commits asset registrations and all ledger movements. A prior successful hash skips parsing and writing; a changed file reuses stable transaction IDs to update effects.
- The adapter registers one aggregate owned position per ticker for net-worth calculations. It reports individual-position lookup as unsupported because the export has no reliable wallet or product identifier.
- Internal wallet transfers and term locks have no aggregate asset effect. Exchange rows subtract the input asset and add the output asset.
- DuckDB stores asset IDs as plain text to avoid requiring a JSON extension at runtime.
- Recent historical prices are fetched from CoinGecko's market chart range endpoint. Older daily closes come from Binance Vision monthly spot ZIP archives, parsed by `binance-client`. The CLI stores traded pair observations, derived asset/USD observations, and confirmed absent pair months in DuckDB, so neither successful archives nor 404s are requested again. Fiat and Nexo fiat proxies use direct quotes where available or Bitcoin cross rates; USD proxies use 1 USD. Binance USDT quotes are treated as USD proxies.
- When Binance lacks an older spot pair, the CLI uses KuCoin daily candles for crypto and ECB reference rates for GBP/EUR. POL tries MATIC archive pairs for dates before its ticker migration. For NEXO months absent from both exchanges, the adapter derives prices from the local export's USD Equivalent and NEXO amount and carries the latest such rate to the next observed row. These are explicit valuation approximations.
- The CLI requests prices only for assets affected by owned transactions, starting one day before each asset's first transaction. DuckDB records fetched half-open intervals per asset/USD pair, so later imports can fill older, newer, or interior gaps without replaying covered ranges. Dense observations in databases created before this table seed conservative coverage; sparse spot prices do not imply a fetched historical interval.
- CoinGecko's fiat exchange-rate endpoint is BTC-based. Crypto assets with direct USD quotes use those; GBP/EUR holdings are valued in USD through paired BTC/fiat and BTC/USD quotes. Binance archive pair candles and resulting asset/USD prices are stored for valuation.
- Net worth is computed from cumulative signed effects at transaction and price timestamps. A nonzero holding without an applicable price causes an error.

## Risks
- Nexo's CSV does not identify all wallet balances or loans; aggregate amounts can be negative if the export omits funding or transfer history.
- Binance archive coverage depends on the asset's spot listing history. Missing prices after all fallbacks are surfaced. USDT may deviate from USD, and NEXO export-implied rates can become stale between rows, so some historical USD valuations are approximate.
